# Project 9: Windows Account Lockout Troubleshooting

## Project Overview
- Ticket ID: ACC-001
- Category: Windows Account and Security Troubleshooting
- Environment: Simulated IT support scenario
- Status: Completed - simulated exercise

## 1. Problem Description

A user reports that they cannot sign in to their Windows work account. A message indicates that the account has been locked after several unsuccessful sign-in attempts.

## 2. Initial Investigation

The support technician should:
- Verify the user's identity according to company policy.
- Record the exact error message.
- Confirm whether the account is actually locked.
- Use authorized account-management tools or contact the administrator.

Security reminder: Never ask a user to reveal their password.

## 3. Investigation Findings

In this simulated case, the administrator confirms that the account is locked.

The user reports that they recently changed their password and may have an old password saved on another device.

## 4. Troubleshooting and Resolution

The authorized support technician:
1. Follows the approved procedure to unlock the verified user's account.
2. Investigates repeated sign-in attempts using authorized tools.
3. Identifies outdated saved credentials on another device in the simulated scenario.
4. Ensures the outdated credentials are corrected through the approved process.
5. Asks the user to sign in using their own credentials.

## 5. Validation

After the simulated correction:
- Confirm that the user can sign in successfully.
- Verify that the account is no longer locked.
- Check whether repeated failed sign-in attempts continue.
- Document the actions taken and the outcome.
- Update the support ticket before closure.

## 6. Security Best Practices

- Verify identity before making account changes.
- Follow company policies for account unlocking and password resets.
- Never request or share user passwords.
- Do not disable security policies to resolve an individual account issue.
- Escalate suspicious sign-in activity to the appropriate security team.
- Follow the principle of least privilege.

## 7. Key Learnings

- Repeated unsuccessful sign-in attempts can result in account lockout.
- Old saved credentials on another device or application may cause repeated authentication failures.
- Account unlocking must follow approved procedures.
- Successful sign-in should be verified before closing the ticket.
- Clear ticket documentation supports future troubleshooting and security investigations.

## 8. Tools and Skills Practiced

- Windows account troubleshooting
- Account lockout investigation
- Identity verification procedures
- Authentication troubleshooting
- Security awareness
- IT service desk ticket documentation
